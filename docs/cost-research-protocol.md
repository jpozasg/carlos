# Cost research protocol (one car → complete TCO)

How every car is researched and costed, so all totals are built the same way and stay comparable. `AGENTS.md` always applies (NULL = unknown; every data point cites a source with quality A–D; English free text; writes only through the API). The reusable agent prompt is `prompts/research-car.md`; the write helpers are `agent_tools.py`.

## Who does what
| Step | Who | Why |
|---|---|---|
| 0. Capture the listing | main agent, in the user's browser | bot-protected sites; see `browser-tasks.md` |
| 1–9. Model research and costs | one research agent per car (several in parallel) | web research and API writes for its own variant, engine, generation and listing only |
| 1–9 for a worker request (#253). Model research, twice | two independent RESEARCH_A / RESEARCH_B runs (Haiku, same prompt `prompts/units/research.md`), writing to staging only | uneven or missed research is the main risk; two runs expose it |
| 1–9b. Disputes | the ARBITER unit (`prompts/units/arbiter.md`), only for material disagreements | settles from the sources, not from which run sounds surer |
| 1–9c. Merge | the MERGE unit (no model, `POST /api/agent/merge`) | agreed and arbitrated findings go through the normal API write path |
| 10. Tax (official calculator) | main agent, browser | official source |
| 11. Insurance | the owner enters a dated quote by hand per listing (dossier, Costs tab); no automated comparison site (2026-11-22) | personal data of the account holder |
| 12. Review, tests, commit | main agent | one place checks totals and consistency |

**Normal flow (C11):** a request from an account runs through the queue: the worker runs CAPTURE, TAX and LISTING, and rows 1–9 as RESEARCH_A and RESEARCH_B, then the ARBITER and MERGE (`prompts/research-request.md`, AGENTS.md "How agents work here"). Row 9 (one in-session research agent per car) is the stop-gap only and follows the same API steps.

**Browser rule (C5, the only one):** the owner's Chrome (Claude in Chrome, a new tab, closed afterwards) is used only where a step names it: capturing the listing, the BMF tax calculator, the reliability pages of step 2 (read by hand, one page per engine or generation) and a figure a plain fetch does not show (the JavaScript-rendered autokostencheck average, the ADAC Pannenstatistik table). Everything else is web search and plain fetch. No browser connected, or several connected with none selected: the run does not pick one; it records the check with `unreachable: no browser` in `notes` and the result the item accepts (see "Checks"), then goes on. CAPTCHAs, Cloudflare checks and logins are never passed.

Research agents never touch another listing or another account's data, never change `project_parameters`, shared sources, repository files, git or the schema.

## Data levels: where a row goes
Every knowledge row is written to exactly one level and inherited by every car below it:
- **engine** (`level='engine'`): oil and filters, spark plugs, timing drive, coolant, drive belt, engine faults (chain rattle, oil consumption, turbo, injectors, wet belt), engine-related faults, engine-level consumption only when no variant page exists.
- **generation**: HU/AU, brakes, wipers, bulbs, battery, suspension, body rust, electrics, interior; chassis faults; tyre size when every engine shares it.
- **engine family vs engine code:** put an engine fault on the engine family when the source names the family or several engine codes of it (`N45/N46`, "all EA211"), otherwise on the engine code; never on both. The contract grades `eng.risks`, `fam.risks` and `rel.ENGINE.engine_specific` on the union of both levels (the listing inherits both, so the cost is the same).
- **variant** (default): the exact HSN/TSN data: consumption (the autokostencheck page of the variant), tax, insurance, tyre size when it differs per engine.
Before writing, read `variant(V)`: rows already inherited must not be written again. If a car shares an engine code or a generation with an existing row, reuse it (`GET /api/engines`, `GET /api/generations`) instead of creating a second one.

## Period and shared conventions
- Window: `km_now` (listing) to `km_now + annual_km × ownership_years` (the account's parameters). Time-based items use the same number of years.
- **DIY** = the jobs the owner does: call `diy_jobs()` (the account's `diy_jobs` preference from the setup wizard; `diy_skills` is an older free-text note; default when unset: engine oil and filters, spark plugs, yearly service, brake pads/discs, battery, bulbs, wipers). **The DIY list (C7, the one rule):** every job in `config.DIYABLE_JOBS` (AIR_FILTER, BATTERY, BRAKES_FRONT, BRAKES_REAR, BULBS, CABIN_FILTER, CLUTCH, COOLANT, FUEL_FILTER, OIL_SERVICE, SPARK_PLUGS, TIMING_DRIVE, WIPERS) carries both prices; the others (BRAKE_FLUID, DRIVE_BELT, DRIVE_COOLANT, GEARBOX_OIL, HU, REDUCTION_GEAR_OIL) are **workshop-only** and carry the workshop price. DIY items carry parts price + hours; workshop items carry the total job price. Hours are shown separately and never priced.
- **Labour rate (owner, 2026-11-22):** the standard workshop labour rate is **EUR 100/h** for every car and every estimate (`config.WORKSHOP_LABOUR_EUR_PER_H`). An estimated labour cost is hours x EUR 100/h, with the hours and their source in `notes`; the owner's own hours are shown, never priced. Other documents refer to this line and do not state another rate.
- **HU/AU** every 24 months at the regional fee (`agent_tools.HU_FEE_EUR`; adjust from the local inspection organisation's fee table and cite it).
- **Tyres:** one set of all-season tyres; standard size of the variant; price = median of 4–5 mid-range all-season tyres in that size; tread life and fitting from `agent_tools` defaults (ADAC tests, tyre shops), cited.
- **Purchase/sale:** the same items for every car for sale (`purchase_sale_defaults`): re-registration, plates, pre-purchase check, with the regional fees from an official fee table cited as a shared source. Deregistration for the reference car.
- **Resale at the end:** `resale_rule_of_thumb` from the asking price unless comparable listings give a better figure (then record those as the source). The rule (ESTIMATED, owner decision 2026-11-23): asking price − loss, floored at 0, with loss = 1,367.4 € × years − 25.28 € × years² + 159.6 € per 10,000 km, where km is the odometer at the end (current km + annual km × years); then a private-sale discount of 10 % (low 20 %, high 5 %; low and high scale the loss by 1.5 and 0.5). Fit: quadratic age and linear km on all 301 cleaned asking prices of the resale fit of 2026-11-23 (cleaning: price 1,000–25,000 €, dropped when above 2.5× or below 0.4× the median of its model within two years); constants in `carlos/config.py`.
- **Reference car (the owned one):** the `resale_end` starts from the car's own `sale_today` value (same condition, defects and basis), then the ownership-years rule; never from asking prices of intact cars, or depreciation turns negative. If `sale_today` is missing, leave `resale_end` unset and put it in the to-do.
- **Fuel:** one real-world source **per drivetrain**, the same for every car of that drivetrain including the reference: for petrol, diesel and hybrid cars the autokostencheck.de real-world average of the exact HSN/TSN variant (`consumption()`); for electric cars the ev-database.org real consumption of the exact variant and battery in kWh/100 km (Wh/km ÷ 10; a modelled real-world figure without charging losses, which the cost adds; owner decision 2026-11-06, #154: Spritmonitor blocks automated readers and autokostencheck has no real-world EV averages) (`consumption(v, value, None, None, None, source_id, electric=True)`). For combustion cars use the **reported average with its number of reports** ("Ø … aus N Angaben", with min and max), never the site's stored catalogue or cost-calculator figure shown elsewhere on the page; note the site's report filter (e.g. 60–125 % of the NEDC figure). Other databases are cross-checks only.
- **Conflicts (one rule for every kind, A9):** the less favourable figure is written and the other quoted in `notes` (`alt: <figure> (<source id or URL>)`); never an average, never a silent choice. Per kind: price or cost → the higher; interval → the shorter km and the shorter months, each on its own (step 4, tie-break note); frequency band → the higher; resale value → the lower; mileage → the higher (PATCH `listings.mileage_km`, log a `correction`); CO2 → the catalogue value of the assumed HSN/TSN until the registration document is seen (the listing value for the tax if the registration period uses CO2). A listing contradiction also gets a `warning` log entry.
- **Estimates (C15, owner 2026-11-22):** a price no source gives is estimated, never copied across and never left NULL when a job needs it: parts from the cited source or a sibling job on a close engine or generation of the same make, plus hours x EUR 100/h, `ESTIMATED`, with the derivation in `notes`: `est: parts <EUR> (<source id/URL or "sibling <job> on <engine>">) + <h> h x 100 EUR/h (<where the hours come from>); basis: <what it was derived from>; alt: <other figure if any>`. NULL stays for consumption, tax and insurance, and for any figure no source or estimate can back.
- **Seller claims** ("timing belt new", "service done") are trusted at no cost, get a `restart(..., 'SELLER CLAIM')` and a checklist item asking for the invoice; if none is shown at the viewing, the cost is added then.
- **Tyres that come with the car:** a new set is a certain cost only when the existing tyres are unusable (age ≥ 8–10 years or worn). Usable summer-only tyres add nothing.
- **Statuses:** `ESTIMATED` for anything derived (say how in `notes`), `VERIFIED` only for official/primary figures for this engine or variant, `PENDING` while unknown (never with a number).

## Electric cars
The same steps, with these differences (owner decisions 2026-11-05; sources in the EV design of #121):
- **Identify:** `fuel_type='Electric'`; the engine is the motor (code from the manufacturer or the type approval) with `power_ps`, `battery_usable_kwh`, `ac_charge_kw`, `dc_charge_kw`; displacement, aspiration, injection and timing drive stay NULL. Plug-in hybrids: `fuel_type='Plug-in hybrid'` and the combustion engine's fields; their energy cost is not supported yet (fuel stays unknown). Full hybrids: `fuel_type='Hybrid'`, costed as petrol.
- **Consumption:** ev-database.org (EVDB), the page of the exact variant and battery: the "Vehicle Consumption" figure of its real-world section (Wh/km → kWh/100 km: divide by 10), recorded with `consumption(v, value, None, None, None, source_id, electric=True)` (metric `EVDB real consumption`, status ESTIMATED, source quality C, `limitations`: "modelled estimate, not owner reports; vehicle side, without charging losses"). Put the page URL and the battery in `notes`. It is the same source for every electric car, the reference included. Winter is inside EVDB's mild/cold blend; no further adjustment. Charging losses are not in the figure: the cost adds `config.EV_CHARGING_LOSS` (8 %, ADAC: 6–10 % at a wallbox) to every kWh, and a household socket's extra 10 % on the home share (ADAC: 13–24 % at a socket), never both twice. **Cross-check:** when ADAC has an Ecotest of the model (measured, including charging losses, quality B), record it as an `observations` row with metric `ADAC Ecotest (incl. charging losses)` and the test date; it is not used for the cost. Spritmonitor is not used: it shows a Cloudflare check that agents must not pass.
- **Maintenance:** no oil, air filter, spark plugs or timing drive. Keep brake fluid, cabin filter, brakes, 12 V battery and wipers (generation), and the electric jobs on the engine: `DRIVE_COOLANT` (battery/motor coolant loop: interval and workshop price, or a check `NONE FOUND` for a lifetime fill) and `REDUCTION_GEAR_OIL` (or a check `NONE FOUND`). HU without AU (no emissions test) at the regional fee.
- **Battery (`eng.hv_battery`):** record the battery warranty (years / km / minimum % health, e.g. 8 years / 160,000 km / 70 %) with a check `FOUND` citing it (quality A/B), and price the high-voltage battery as one `fault()` on the engine (component code `HV_BATTERY`, a band or curve with its reason; replacement typically €6,400–16,500). Never a second battery row per listing.
- **Reliability:** the engine slot is the same Autoscore / EngineScope lookup; there are no parts any more. Faults of the electric drivetrain carry `part` `ENGINE` (motor, inverter, high-voltage battery and its management, on-board charger and charge port, thermal management/heat pump) or `GEARBOX` (reduction gear and driveshafts).
- **Listing facts for filters and distance:** Structured facts for the ranking filters, the distance and the dossier (#169) go in `listing` as the ad states them (null when not shown, never guessed): `seller_type` DEALER/PRIVATE, `warranty` 1/0, `hu_until` YYYY-MM (HU/TÜV month), `service_history` YES (Scheckheft/invoices shown) / CLAIMED (only stated) / NO, `accident_free` YES (documented) / CLAIMED ("unfallfrei" stated) / NO, `postal_code` (the car's 5-digit postcode) and, for a **dealer ad, always** the dealer's rating: `seller_rating` (stars, e.g. 4.8) and `seller_reviews` (count) from the rating line (mobile.de "Händlerbewertung"); null for a private seller.
- **Listing:** the seller's battery health figure goes in `battery_soh_claim` (%); `capture_listing.py` adds the checklist item asking for a SoH certificate (method, date, km; ADAC guide ≥ 88 % at 100,000 km) to every electric listing.
- **Tax:** the BMF calculator with the permitted total weight, recording the annual amount **after** the exemption; the calculation applies the exemption itself (first registered by 2030-12-31: 10 years, until 2035-12-31 at the latest), so a car exempt for the whole period needs no tax row.
- **Resale:** comparable listings first; without them `resale_rule_of_thumb(L, electric=True)` takes the low case as the expected value (DAT: 3-year-old electric cars keep 51.5 % of the list price vs 62.7 % for petrol).
- **THG-Quote:** information only (volatile, broker-dependent); never deducted from the cost.
- **Charging:** the account's answers (setup step Charging) set the electricity price; nothing to research per car.

## Hybrids
- **Full hybrid** (self-charging, e.g. Toyota 1.5 Hybrid): `fuel_type='Hybrid'`, never `Petrol` with a note (the fixed code drives the contract and the fuel price). Costed as petrol: autokostencheck consumption, petrol price, petrol maintenance (oil, filters, plugs, timing drive). The hybrid battery and inverter are priced faults on the engine when a source names them; Toyota-style hybrids often have no published service plan, so say which intervals are estimates.
- **Plug-in hybrid:** `fuel_type='Plug-in hybrid'` and `battery_usable_kwh`; researched like a combustion car (its combustion engine needs the full petrol schedule) plus the battery warranty check. Its energy cost is not supported yet (it depends on the charging share): the fuel component stays unknown and the to-do says so.

## Steps for one car
**New account:** run `shared_sources()` once first; it registers the shared reference sources (registration and plate fees, pre-purchase check, depreciation rule of thumb, HU/AU fee, tyre test) that `purchase_sale_defaults`, `hu`, `tyres` and `resale_rule_of_thumb` cite, and does nothing when they exist.

Start with `todo(listing_id=L)` and `todo(vehicle_id=V)`, read the listing (`listing(L)`: description, attributes, claims, photo count) and the variant (`variant(V)`: engine, generation, inherited rows).

1. **Identify the car**: PATCH `generations/<id>` (name and code, start/end of sale, facelift year), `engines/<id>` (code, description, fuel, displacement, power, aspiration, injection, timing drive) and `vehicles/V` (trim, gearbox, body, emissions, CO2, HSN/TSN). Sources: ADAC Autokatalog (HSN/TSN, tyres, engine), Wikipedia, manufacturer data, dieversicherer.de for HSN/TSN candidates. A TSN not on the listing is recorded as the best candidate with "assumed" in `notes`; the user confirms it from the registration document (field 2.2). Set `status`/`technical_status` to `VERIFIED` (two agreeing sources) or `PARTIAL`.
**Contract v10 (#357):** the reliability checks `rel.<PART>.<source>`, `rel.coverage`, `gen.baseline` and `var.gearbox` are replaced by the five `rel.*` source items in the table below (fixed external sources per level, #351). Recall research (`gen.recalls`) and fault research (`*.risks`) are unchanged.

2. **Reliability: a harness for fixed sources (#351).** Carlos does not research reliability itself. It maps each level to the same external sources for every car, records what they publish (verbatim, never reinterpreted) and links to them. The reliability score is the mean of the slots that have a figure (`docs/ranking.md`); a missing source is coverage, never a zero.
   - **Engine level: Autoscore** (`AUTOSCORE`, C): page `https://autoscore.pro/engine/<slug>` (no `/de/`). Record `source_key(...)` with the slug as `external_key`, then `rating(...)` with the risk score 0-10 as `value_num` and the verdict verbatim as `value_text`, edition = the reading date. Not listed (e.g. BMW N45): check `rel.autoscore` `N/A` with the reason. Own-use terms: the page is read for personal use or internal decisions; the issue table and its cost estimates are not stored and never enter a TCO component.
   - **Engine level: EngineScope** (`ENGINESCOPE`, C): page `https://enginescope.gr/engine/<slug>/`. **Link only** while `config.ENGINESCOPE_PERMISSION` is `NONE`: record `source_key(...)` and nothing else; the API refuses a score or cost range (403) until the owner has written permission from EngineScope (terms section 6: no reproduction or derivative works; section 7: no scraping). Not listed: check `rel.enginescope` `N/A`.
   - **Generation level: TÜV-Report** (`TUEV_REPORT`, B): the series name as printed is the `external_key`; one `rating(...)` per age class (`age_from`, `age_to`, `value_num` defect share %, `class_average`), edition = report year. The whole table is imported once a year from the owner's copy; a run only maps its generation to an existing series name (`source_key`), or records `rel.tuev` `N/A` "not in the report".
   - **Generation level: ADAC Pannenstatistik** (`ADAC_PANNENSTATISTIK`, B): the series as printed; one `rating(...)` per registration year (`reg_year`, `band` 1 best to 5 worst, `value_num` the figure, `sample_count` when shown), newest edition; the table is drawn by JavaScript, so it is read in Chrome. For cars over 10 years old the Gebrauchtwagen-Info table of an earlier edition may supply the year. Too new or too few registrations: `rel.adac` `N/A` with the reason.
   - **Generation level: ADAC Gebrauchtwagen-Info** (`ADAC_GWINFO`, B): one PDF per generation and fuel (`fuel_type` on the `source_key`; NULL = every fuel), found with `site:assets.adac.de GWInfo <make> <model>` (there is no index). Link only; its weak points ("Haeufige Bauteilfehler") and the Autoscore issue list are the **discovery sources for faults**. No PDF: `rel.adac_gwinfo` `N/A` "no report found".
   - **N/A is a check, not silence:** `check(level, id, 'rel.<source>', source_id, 'N/A', '<why>')` with a level-free shared `sources` row for the source and edition. The key rows carry `source_id`, `url`, `checked_date`.
   - **Reading:** by hand under the Browser rule above, one page per engine or generation, never in bulk, never scraped, never past a CAPTCHA or login (`docs/browser-tasks.md`).
   - **Faults and recalls are unchanged.** Every weak point GW-Info or Autoscore names for this engine or generation becomes a priced `fault()` (never both a fault and anything else for the same defect), or the `*.risks` check notes say why not; frequency, shape and prices follow "Faults: frequency and shape". A **manufacturer recall** is its own row with `recall=True` and an `inspection_action` that names the check; `checklist_from_reliability(L)` gives it a checklist item, linked by `recall_id`. Recall research continues (owner, 2026-11-10).
   - **Only recalls that can apply to this car:** check the engine, gearbox and build window against the car (first registration as the latest possible build date). A recall for another engine is written on that engine or not at all; one whose build window starts after this car's first registration is not written for it. When it cannot be decided, write it and leave its checklist item PENDING for the owner's VIN check.
   - **Recalls (#333):** try the sources in this order: KBA Rückrufdatenbank (A), the manufacturer's recall page (A), the ADAC recall list (B), one aggregator such as CarWiki (C). A source that is unreachable or blocked gets `check('generation', G, 'gen.recalls', source_id, 'N/A', 'unreachable: <reason>')` and you continue down the list; the first reachable source gives `FOUND` or `NONE FOUND` (only those two satisfy `gen.recalls`; N/A records the attempt). Stop after the first reachable A or B source; with only a C source reachable the item is ACCEPTED, not VERIFIED. Recall `code`: the KBA reference when any source gives it (`KBA-14729R`), otherwise `<MAKE>-<YYYY-MM>-<COMPONENT_CODE>` (month of the announcement, code from `fault_components`, e.g. `VW-2019-08-CAM_ADJUSTER`); never `UNKNOWN-...` or prose (the API refuses it).
   - **Phase windows** (#153): a generation is the whole production run (facelift year a field). A maintenance item, fault or recall that concerns only part of it takes `applies_from` / `applies_to` (first registration, `YYYY-MM`): a fault the facelift fixed (`applies_to` = the month before the facelift), a recall's build range, a job that changed with the facelift. A listing outside the window does not inherit the row; one without a known first registration keeps it. Never split ordinary facts that hold for the whole generation, and never make a second generation for a phase.
   - **Generic wear is not a weak point (owner, 2026-11-22).** Clutch, brake pads and discs, battery, bulbs and wipers wear on every car: their cost is a maintenance item (`item(..., job=...)`, `kind='WEAR'`, with its `job` code), and a part worn out now or overdue is certain maintenance (step 6), never a repair. They become a `fault()` only when a source flags them for this model or engine as above average (e.g. "clutch wears early", a known dual-mass flywheel fault), and the row says which source.
3. **Consumption** (`consumption()`), one rule for every run (C6, A1): (a) the autokostencheck page of the exact HSN/TSN variant; (b) no page for it, or the ad has no HSN/TSN: the page of the same make, model, fuel and power (kW) whose production window contains the first registration; if several, the one with most reports; if none has that power, the nearest kW of the same engine family, said in `notes`; (c) the reported average with its number of reports, min and max ("Gemeldeter Durchschnitt … Grundlage sind N Meldungen"), never the stored catalogue figure or the "Praxisverbrauch" shown elsewhere; the block is sometimes rendered by JavaScript, then it is read in the browser under the Browser rule; (d) a page showing only the stored figure: the next page in the order of (b) that has a reported average; (e) none: `var.consumption` `NONE FOUND` with the URLs read in `notes` (`unreachable: <URL> <reason>` where a page could not be opened). Figures of different pages are never mixed. Other databases are cross-checks only; electric cars: "Electric cars".
4. **Maintenance schedule** (`item(..., job=...)` per job at its level, `hu(v)`): manufacturer intervals (km and months) from service plans or manuals. Every job gets its `job` code (`config.JOBS`; the contract finds jobs by it) and, since the research is shared and each account's DIY choice picks one price at calculation time, **both prices** for every DIY-able job (the list under "Period and shared conventions"): DIY parts from shops and the workshop price of the whole job; workshop-only jobs the workshop price. A price no source gives is estimated (see "Estimates" above), never the other price instead. Note the source of every price (quality D for search snippets). **Interval source order and tie-break (#341):** (1) go down the tiers and stop at the first that gives the job for this engine code: A the manufacturer's service plan, owner's manual or service booklet; B ADAC, an authorised dealer page, Haynes/Bucheli; C aggregators (autodoc club, carwiki, repareo); D forums. (2) When the maker offers two regimes (flexible/long-life vs fixed, e.g. VW LongLife 30,000 km/24 months vs fixed 15,000 km/12 months, BMW CBS), take the **fixed** regime (a used car's oil and driving history is unknown) and say so in `notes`. (3) When sources of the **same tier** disagree, take the **shorter km and the shorter months, each on its own**, and write `Interval: shorter of <source A km/months> and <source B km/months> (tie-break).` in `notes`; raise no flag for this. (4) A preventive interval shorter than the maker's only from a B-or-better source naming this engine (or two C sources). (5) Write **both** km and months whenever any source in the chosen tier gives both; NULL only when no source gives that dimension. (6) No source at all for the job: it stays missing in the to-do. Use the manufacturer's **normal-use** interval; when a reliable source says it is too optimistic for this engine (long-life oil services, "lifetime" fluids, wet belts, direct-injection or turbo engines), use the shorter preventive interval and begin `notes` with "Preventive interval:" plus the reason, the source and the manufacturer's figure. Never shorten without a stated reason. `VERIFIED` only with an A or B source for this engine; otherwise `ESTIMATED` saying what was not found. If a better source changes the interval of a job that is also a certain repair or a restart, check that the certain repair is still due.
5. **Faults** (`fault()` at its level): each known failure of this model with a frequency band and shape or a sourced curve, the consequence, and a price (parts + labour, or DIY parts + hours); the method is in `docs/prompts/research-car.md`, "Faults (#168)". Age-driven items (battery, rust) use the AGE shape. **Every fault gets a price**; when none is found, estimate parts and labour from similar jobs (labour = hours x EUR 100/h, see Period and shared conventions), the derivation in `notes`. Engine damage, body rust and similar large faults are priced too, with a realistic band. A fault the car has now is a certain repair of the listing (step 6), not a probability.
6. **Certain one-off costs of this car**, each with an `item` that names the job and why it is due ("Timing belt kit with water pump (due by age: 11 years, limit 10)"):
   - **Service book vs. jobs due by age:** a claim naming the job ("Zahnriemen neu", "Bremsflüssigkeit gewechselt") is trusted as `restart(..., 'SELLER CLAIM')` plus a checklist item asking for the invoice; a document showing it is `DOCUMENTED`. A generic "Scheckheftgepflegt" / "service history" covers only the routine yearly service (oil and filters); it does **not** cover jobs due by age or km (timing belt or chain kit, coolant, brake fluid, spark plugs): when one of those is overdue and not documented, it is certain maintenance. The same rule for every car.
   - **Maintenance due at purchase** (`certain(L, 'maintenance', ...)`): a job from the maintenance schedule that is due now or overdue and not documented as done (timing belt or chain kit by interval, coolant, brake fluid, spark plugs, service). It is maintenance, not a repair, even when overdue. Always `restart(L, item_id, 'CERTAIN REPAIR', source_id, unit_cost_id)` so the schedule restarts and the job is not counted twice.
   - **Repairs** (`certain(L, 'repairs', ...)`): a fault this car has now (a stretched chain the owner reports, a leak, a broken or seized part, a defect in the HU report). Worn pads, discs, clutch, battery and fluids are maintenance, see step 2.
   - **Tyres** (`certain(L, 'tyres', ...)`): see the tyres rule above.
7. **Tyres** (`tyres()` at the variant or generation): standard size and median price; the size on the listing photos overrides when visible.
8. **Purchase/sale and resale** (`purchase_sale_defaults(L)`, `resale_rule_of_thumb(L)`).
9. **Listing checks and log**: checklist items for every seller claim to verify (HU, service book, new parts, owners); `warning` entries for red flags (price far below market, contradictions); a final `verification` entry summarising what was researched.

## The research contract (what "researched" means)
`carlos/research.py` lists what must be known on each level; `GET /api/agent/schema` → `research_contract` publishes it, and `todo()` reports every missing item (`catalogue` per generation, engine and variant on its own; `models` per variant with its engine and generation). Each item is graded from the rows **on its own level**, so a level counts as researched the same way whichever listing triggered the research:
- **MISSING**: nothing acceptable, a source below the item's minimum quality, or a check recorded against an older contract (`since`).
- **ACCEPTED**: present, but `ESTIMATED` or from a C/D source. A row found one level too low (an engine job on the variant) counts as ACCEPTED at most, and the to-do says to move it.
- **VERIFIED**: a verified, official or primary row from an A/B source; for a check, an A/B source.

A level is **researched** when no item is MISSING and **verified** when every item is VERIFIED. The confidence criterion is the mean grade of the variant's, its engine's, its generation's and its listing's items (VERIFIED 1, ACCEPTED 0.5, MISSING 0).

**Checks** (`check(level, id, task, source_id, result, notes)`, table `research_checks`) record a task done on one level. One table decides the result (C17; `research-audit` SKILL.md section 2 refers here). Write one per source consulted, also when the source lists nothing:

| Situation | Record | `notes` must hold |
|---|---|---|
| A reachable source for this level lists the thing | `FOUND` (+ the rows) | the URL |
| A reachable source for this level lists nothing ("consulted, nothing to report": a clean part counts as researched) | `NONE FOUND` | the URL, and what the page covers |
| The item does not apply, or the source does not cover the level (no facelift, never tested, not listed, too new for TÜV/ADAC) | `N/A` | the reason; the URL or search when it is a source's claim |
| The source cannot be opened (404, CAPTCHA, Cloudflare, login, no browser) | the result the item accepts ("Accepted results" in the table below), then the next source in the item's order | `unreachable: <URL tried> <reason>` |

A check with a `NONE FOUND` or `N/A` result names the URL read or the search made (`site:` query). A `NONE FOUND` on a `*.risks` item while faults exist on that level is wrong. An `unreachable:` check is open: it is re-done when the source or a browser is available. Only the results in "Accepted results" satisfy an item (`carlos/research.py` ITEMS; a test keeps this table in step with it).

## Faults: frequency and shape (owner, 2026-11-06, #168)
Faults (`fault()`, table `faults`) replace weak points and repair risks; one row per design fault on exactly one level (engine family, engine, gearbox family, gearbox, generation, body style, option, variant). Every fault gets a price and a probability, found the same way for every car. Every fault gets a `component_code` from `fault_components` of `GET /api/agent/schema` for its part (`code=` in `fault()`). Pick the code of the component that fails, not of the symptom (oil loss from a valve cover gasket is `OIL_LEAK`, oil burnt through the piston rings is `OIL_CONSUMPTION`). `OTHER` only when no code fits, with `notes` saying what it is. Two faults with the same code on one car are the same fault unless you say why not (`distinct_of`).
1. **Frequency band** from what the sources say, by 200,000 km or 15 years (the central value counts, the range is stored): `systemic` 50 % (40–70; needs `manufacturer_trace`: extended warranty, goodwill, TPI or class action), `widespread` 25 % (20–40), `common` 12 % (8–20), `occasional` 5 % (3–8), `rare` 1.5 % (0.5–3). A fault only forums report is one band milder and never above `common` (the API refuses it). A real statistic replaces the band with an explicit `curve_km` / `curve_age` (`probability_basis='STATISTIC'`). Quote the sentence the band rests on in `quote`.
2. **Shape**: `WEAR_KM` (grows with km), `AGE` (grows with years: rubber, rust, batteries), `WINDOW` (happens within `window_km` after `onset_km`, then stops) or `RANDOM` (even over life). Every curve continues to 300,000 km / 20 years; the expected cost is the conditional chance over the owner's km (or years, the larger counts) × the price.
3. **Fixes and warranty**: a documented fix of the car (listing history `DONE`) means the part is new from that km (owner rule 2026-11-22): the fault's own curve restarts there (the chance over the owner's period, not zero), with the age curve restarted at the DONE date when it is known (otherwise the age part is unknown and the km curve alone applies); a `fixed_fault_id` instead follows the replacement part's curve from there; an unknown km at the fix is unknown, never 0; the owner's own chance (`owner_probability`) overrides both. "fixed from" a build date needs an A/B source, otherwise the fault stays with `window_uncertain=1`. An extended warranty (`warranty_km`, `warranty_years`, `warranty_share`) lowers the cost while it applies.
4. **Severity is derived**: HIGH for ENGINE_DAMAGE or a price ≥ €1,500, and for STRANDS or SAFETY from €500 (cheaper: LOW-MEDIUM, #285); MEDIUM ≥ €500 or UNUSABLE; LOW otherwise. Every recall scores HIGH IF APPLICABLE until its check is OK/N/A.

**Checklist (#223):** every fault that can be seen or tested at a viewing carries an `inspection_action` (a concrete check: what to look at or ask for); a fault without one gets no checklist item. Every listing also gets the fixed item "Ask a brand dealer for an open-recall check by VIN". After adding or changing faults and recalls, run `checklist_from_reliability(L)` again: it adds only the missing items (faults with an action, recalls, the VIN item) and is safe to repeat.

**Retired with #351:** `reliability_stats`, the statistics-vs-faults consistency check (`STATS_MISMATCH`), review flags and `FOLLOW_UP` requests are gone; the old tables are kept read-only. A disagreement between two sources is settled by the less-favourable-figure rule: quote the other figure in `notes`.

## Definition of done
- `todo(vehicle_id=V)` and `todo(listing_id=L)` are empty except owner decisions (verdict) and items that need the user (TSN confirmation); the variant's `state` is `researched` or `verified`.
- `GET /api/listings/L` shows every TCO component not NULL and `tco_complete` true.
- Every fault has a price (estimated when necessary, EUR 100/h, derivation in `notes`); every combustion engine has aspiration, injection and timing drive; every electric engine its usable battery kWh and AC charging power.
- The agent's report lists: what was written (rows per table and level), every assumption (TSN, sizes, intervals), faults priced only by estimate, questions for the user.
- Main agent: `python -m unittest`, integrity check, commit of the data repository, push.
