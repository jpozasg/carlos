## Unit ENGINE (level id = engine)
Owns the engine and its family: `eng.identity` (code = the manufacturer's engine code (EB2, CJZC, …): PATCH `engines/<id>` when the shell holds an 'UNKNOWN-…' placeholder or a descriptive name, because the catalogue key is code + power; fuel, displacement, power, aspiration, injection, timing drive; electric: `eng.identity_ev` with usable battery kWh and AC charging kW), the jobs `eng.oil`, `eng.air_filter`, `eng.spark_plugs` (petrol/hybrid) or `eng.fuel_filter` (diesel), `eng.timing_belt` (belt) or `eng.timing_chain` (chain/gear: a job or a check `NONE FOUND`), `eng.coolant` (job, or a check `NONE FOUND` citing the lifetime fill); electric: `eng.drive_coolant`, `eng.reduction_gear_oil` (job or check) and `eng.hv_battery` (check on the battery warranty plus one priced HV battery risk); `eng.risks` and `fam.risks` (engine faults, each priced, or a check `NONE FOUND`); the check `rel.ENGINE.engine_specific` on the engine family.
Start: `todo(vehicle_id=<the listing's variant>)` (`listing({LISTING_ID})`), `GET /api/engines`. Write with `engine(...)`, `item(v, ..., level='engine', job='<JOB>')` (both DIY parts and workshop price for DIY-able jobs; manufacturer normal-use interval, shortened to a documented preventive interval only with a stated reason beginning "Preventive interval:"), `fault(v, ..., level='engine')`, `reliability(...)`, `check('engine' | 'engine_family', id, '<item id>', source_id, result, notes)`. Protocol steps 1, 4, 5 and the section for the drivetrain (petrol / diesel / full hybrid / plug-in hybrid / electric; an electric car has no oil, filters, plugs or timing drive).
No browser. Last line: `CARLOS_RESULT done: <summary>` or `CARLOS_RESULT failed: <reason>`.
