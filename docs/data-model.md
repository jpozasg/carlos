# Data model

SQLite, one file (`cars.sqlite` in the data directory). `schema.sql` is the executable reference and the baseline for new databases; changes go through `migrations/NNN_*.sql`. Every row of a top-level table belongs to one account (`owner_id`); child rows belong through their parent. The API shows and accepts only the rows of the account behind the session or token (per-owner views, `carlos/auth.py`).

**Shared catalogue** (issue #109): `generations`, `engines`, `vehicles` and level-attached `sources` with `owner_id` NULL are shared by every account; with an owner they are private to it. An account sees a catalogue variant (with its engine, generation, knowledge rows and sources) only through `catalogue_links` (`owner_id` + exactly one of `vehicle_id`, `engine_id`, `generation_id`), which a listing creates for its variant; admins (the curator and the shared research worker) see the whole catalogue. Knowledge rows carry `owner_id` too: NULL follows its level (shared on a catalogue level), set = a private row of that account on a shared level — the server sets it for insurance premiums and `USER DATA` figures. Level-free sources with `owner_id` NULL are global (fee tables); listing and user sources keep their owner. Natural keys keep the catalogue free of duplicates (migration 033): a generation by make + model + name, an engine by code + power, a variant by HSN/TSN + engine. The research reset (`python research_reset.py <cars.sqlite> [--apply]`, issue #194; dry run by default) empties all model research and keeps one account's listings, with `listings.vehicle_id` empty until the worker re-researches them (the part-6 promotion tool of #144 was retired with it).

| `project_preferences` | free preferences per account (`owner_id`, `preference_key`, `preference_value`, `unit`, `status`, `notes`): search area, preferred fuel/engine/gearbox, DIY skills, usage profile. Keys the setup wizard writes (plain English values): `search_center`, `search_radius` (km or `Any`), `preferred_fuel`, `preferred_transmission`, `driving_mix`, `current_car`, `diy_jobs` (comma list, `none` when a workshop does everything), insurance profile for comparison quotes: policyholder `insurance_holder_gender` (`female`/`male`/`diverse`), `insurance_holder_birth_date`, `insurance_holder_licence_date` (ISO dates), `insurance_holder_licence_country` (`germany`/`eu`/`other`), `insurance_holder_marital` (`single`/`married`/`partnership`/`divorced`/`widowed`), `insurance_holder_occupation` (`employee`/`worker`/`public_service`/`civil_servant`/`self_employed`/`student`/`trainee`/`retired`/`homemaker`/`not_working`), `insurance_holder_bf17`, `insurance_holder_other_car` (`yes`/`no`), `insurance_holder_points`; `insurance_drivers` (JSON array of further regular drivers, each with `relationship` `partner`/`child`/`other`, `household` `yes`/`no` and the same person fields except licence country); `insurance_main_user` and `insurance_keeper` (Policyholder / Driver 2 / Someone else); policy `insurance_start_date`, `insurance_claims_3y`, `insurance_previous_insurer`, `insurance_previous_years`, `insurance_cancelled`, `insurance_usage`, `insurance_parking`, `insurance_seasonal_plate`, `insurance_workshop_binding`, `insurance_discounts` (comma list of `homeowner`, `children` (under 17), `transit_pass`, `bahncard`, `club`, `liability`, `household`, `legal`, `accident`, `other_policy`, or `none`); `insurance_usage` (Private (including commuting) / Business only / Private and business, as CHECK24 asks), `insurance_club_name`, `insurance_liability_insurer`, `current_premium_eur_year` (the wizard also sets the parameters `drivers_count` and `driver_age` from the people entered); this personal data lives only in the account's database rows, never in notes, logs, dossiers or `insurance_data.quote_profile` (which records the profile without birth dates); `onboarding_done` (date, or `skipped`). Older free-text keys (`diy_skills`, `usage_profile`, `preferred_engine`, …) are kept and shown as notes. |

## Three levels of model knowledge
| Table | Level | Columns |
|---|---|---|
| `generations` | generation | `make`, `model`, `name` (generation code or name), `start_year`, `end_year`, `facelift_year`, `status`, `notes`, `owner_id`. |
| `engines` | engine | `code` (manufacturer engine code), `family`, `description`, `fuel_type` (Petrol / Diesel / Hybrid / Plug-in hybrid / Electric), `displacement_cc`, `cylinders`, `power_kw`, `power_ps`, `aspiration` (NATURALLY ASPIRATED / TURBO / SUPERCHARGED), `injection` (PORT / DIRECT / DUAL / CARBURETTOR), `timing_drive` (CHAIN / BELT / WET BELT / GEAR); for an electric engine `battery_usable_kwh`, `ac_charge_kw`, `dc_charge_kw` instead of displacement, aspiration, injection and timing drive (NULL), `status`, `notes`, `owner_id`. |
| `vehicles` | variant | `generation_id`, `engine_id`, `trim`, `transmission`, `body_style`, `model_year`, `emissions_standard`, `co2_g_km`, `hsn`, `tsn`, `technical_status`, `notes`, `owner_id`. |

**Knowledge tables** attach to exactly one level through `vehicle_id`, `engine_id` or `generation_id` (a CHECK constraint enforces it). A listing resolves its data from its variant, its engine and its generation together (`carlos/db.py: for_variant`). The `level` of every row is returned by the API.

| Table | What a row is | Key columns |
|---|---|---|
| `maintenance_items` | a scheduled job (`schedule='ITEM'`; old `PACKAGE` rows are history, `active=0`) | `item`, `job` (controlled code, `config.JOBS`: the research contract matches jobs by it, and each account's DIY choice decides per job whether the DIY parts or the workshop price counts; `diy` is only the default for rows without a job), `interval_km`, `interval_months`, `diy` (0/1), `diy_parts_cost_eur`, `diy_hours`, `reference_cost_eur` (workshop price of the whole job), `labor_included`, `status`, `source_id`, `notes`, `active` |
| `repair_risks` | a failure that may happen in a km window | `component`, `job` (plain replacement jobs: clutch, battery, bulbs, timing drive; the account's DIY choice decides whether labour counts), `km_from`, `km_to`, `probability` (0–1 over the window, with the reason in `evidence`/`notes`), `parts_eur`, `labor_eur`, `diy`, `diy_hours`, `status`, `evidence`, `source_id`, `notes` |
| `reliability_items` | a documented watch point (not a proven defect) | `component`, `issue`, `evidence`, `severity` (HIGH / HIGH IF APPLICABLE / MEDIUM / LOW-MEDIUM / LOW), `frequency_status`, `source_id`, `inspection_action` (becomes a checklist item of every listing), `part` ENGINE / GEARBOX / CHASSIS / ELECTRICS (required on insert; each part starts at 9 and loses its 3 worst points, reliability out of 36, higher is better), `is_recall` (a recall costs its points until its checklist item is OK or N/A) |
| `observations` | a measured figure, above all consumption | `category`, `metric` (`Autokostencheck average` is the primary consumption; `Owner measured average` a cross-check), `value_num`, `value_text`, `unit`, `sample_count`, `min_value`, `max_value`, `status`, `evidence_quality`, `observed_date`, `source_id`, `notes` |
| `tax_data` | annual road tax | `annual_tax_eur`, `status`, `basis` (every input of the calculator), `registered_from` / `registered_to` (`YYYY-MM`, optional: the first-registration window the row applies to; a listing uses the row whose window covers its first registration, NULL = any), `source_id`, `notes` |

**Phase windows** (#153): `maintenance_items`, `repair_risks` and `reliability_items` have optional `applies_from` / `applies_to` (`YYYY` or `YYYY-MM`, first registration). A listing inherits a row only when its first registration falls inside (a new car counts as registered today; an unknown registration keeps the row). A generation is the whole production run; phases are windows, not generations.

| `insurance_data` | a quote or the premium paid | `hsn`, `tsn`, `year`, the three Typklassen, `annual_premium_eur` (median of the 5 cheapest reasonable offers), `premium_min_eur`, `insurer`, `tariff`, `premium_status` (QUOTE / USER DATA / PENDING), `quote_date`, `quote_profile` (JSON, no personal data), `source_id`, `notes` |
| `tyre_data` | the tyre set of the variant | `tyre_type`, `size`, `price_per_tyre_eur`, `tyres_per_set`, `life_km`, `fitting_per_set_eur`, `status`, `source_id`, `notes` |
| `research_checks` | a research task of the contract done on this level (issue #114) | `task` (a contract item id, e.g. `rel.ENGINE.adac`, `gen.recalls`), `source_id` (required), `result` (`FOUND`, `NONE FOUND`, `N/A`), `contract_version`, `checked_date`, `notes`, `named_codes` (JSON array of `fault_components` codes of the task's part that the source names as weak points; migration 042, #343), `archived` |

`sources` (`title`, `url`, `source_type`, `quality` A–D, `accessed_date`, `supports`, `limitations`, `owner_id`) may attach to one level or to none (shared sources such as fee tables).

## Target design levels and knowledge (migration 028, #174)
Being built from `docs/target-design.md`; the old tables (`reliability_items`, `repair_risks`, premium rows of `insurance_data`, `maintenance_resets`, `unit_costs`) stay until the research reset (#167) drops them.
- **Levels** (shared catalogue, `owner_id` NULL, written by admins): `engine_families` (engines.`family_id`), `gearbox_families` → `gearboxes` (code, type `MANUAL`/`DCT`/`AT`/`CVT`/`SINGLE-SPEED`, gears; vehicles.`gearbox_id`), `body_styles` (per generation; vehicles.`body_style_id`), `options` (convertible roof, sunroof, xenon, air suspension, 4×4; a listing's options in `listing_options`). Unique by name/code.
- **Knowledge on any level** (`vehicle_id`, `engine_id`, `generation_id`, `gearbox_id`, `engine_family_id`, `gearbox_family_id`, `body_style_id`, `option_id`; exactly one): `faults` (component, part, consequence `ENGINE_DAMAGE`/`STRANDS`/`SAFETY`/`UNUSABLE`/`COST`/`COSMETIC`, prices, existence `CONFIRMED`/`REPORTED`, cumulative curves `curve_km`/`curve_age` as `[[x, share], …]`, `probability_basis`, `usage_flags`, `usage_multiplier` only with `usage_source_id`, build window), `recalls` (code, defect, remedy, safety, build window or `window_known` 0), `research_checks`; `maintenance_items` gains every level, `kind` `JOB`/`WEAR` (wear parts with their typical life as interval) and heavy-use intervals; a maintenance row **without a level is a global default** (HU, brake fluid, labour rate) that a level row with the same job overrides. `market_models`: per generation + engine (+ gearbox), the value at a reference age/km and the share lost per year and per 10,000 km, with the three band counts and the sample date.
- **Listing facts** (private, survive the reset): `listings.build_date`, `engine_code_seen`, `hsn`, `tsn`, `trim` (copied from the current variant); `listing_quotes` (insurance quotes, copied from the account's premium rows; new quotes, by the owner's session or the worker's INSURANCE unit, are written here; consent preference `insurance_worker_quotes` in `project_preferences`); `listing_history` (a job, fault or recall: `DONE`, `PRESENT` (a certain cost), `OPEN`, `NOT AFFECTED`; evidence `DOCUMENTED`/`SELLER CLAIM`/`OBSERVED`/`VIN CHECK`).
- **Fault probability (migration 029, #168):** `faults.frequency_band` (`config.FREQUENCY_BANDS`) with `share_low`/`share_high`, `shape` `WEAR_KM`/`AGE`/`WINDOW`/`RANDOM` (`window_km`, `onset_km`), `manufacturer_trace`, `fixed_fault_id`, `warranty_km`/`warranty_years`/`warranty_share`, `quote`. `component_code` (migration 039, #221): the controlled component of the fault (`config.FAULT_COMPONENTS`, per `part`), NULL on old rows until back-filled; `component` stays the readable name.
- **Review flags (migration 030, #168):** `review_flags` (one level, kind `STATS_MISMATCH`/`SOURCES_DISAGREE`/`FIX_UNCERTAIN`/`OTHER`, `what`, `why`, status `OPEN`/`CLEARED`) and `flag_reviews` (worker, date, outcome `CONFIRMED`/`RESOLVED`, conclusion, finding). The API never clears a flag by PATCH; two different workers resolving it with the same conclusion do. The statistics-vs-faults check that raised `STATS_MISMATCH` and queued `FOLLOW_UP` requests went with `reliability_stats` (#353).
- **Reliability sources (migration 043, #353, plan #351 §2):** reliability comes from a few fixed external sources, each on the level it covers, recorded verbatim (shared catalogue, `owner_id` NULL, admin-written). `source_keys`: one row maps one level (`engine_id` or `generation_id`, exactly one) to one source's page: `source_key` (`AUTOSCORE`, `ENGINESCOPE`, `TUEV_REPORT`, `ADAC_PANNENSTATISTIK`, `ADAC_GWINFO`; checked by the API against `config.RATING_SOURCES`, not in SQL; written through `POST /api/agent/source_keys`, #354), `fuel_type` (GW-Info only; NULL = every fuel), `external_key` (the source's slug, series name or file name as published), `url` (https), `source_id`, `checked_date`; one live key per source, level and fuel. `source_ratings`: what the source publishes per `external_key` (matched case-insensitively, so engines sharing one page store the rating once) and `edition` (report year, or the reading date for undated sources): `age_from`/`age_to` (TÜV age class) or `reg_year` (ADAC first registration), `value_num` (Autoscore risk 0–10, EngineScope 0–100, TÜV %, ADAC PKZ), `value_text` (verdict or band as printed), `band` 1 (best)–5 (worst, ADAC), `class_average` (TÜV), `cost_min_eur`/`cost_max_eur` (EngineScope, only with written permission), `sample_count`, `url`, `source_id`, `checked_date`; one live row per source, key, edition and class or year. A new edition inserts new rows and archives the old ones. `reliability_stats` (TÜV/ADAC per age class, always empty) is dropped; `recalls`, `reliability_items` and `review_flags` stay as they are, `faults` and `repair_risks` unchanged.
- Visibility follows the levels: an account sees a family, gearbox or body style through the variants of its listings, an option through its generation; knowledge rows when their level is visible.

## Listings (a specific car)
| Table | Purpose |
|---|---|
| `listings` | one row per car: `vehicle_id` (variant), `source_id` (the listing itself as a source), `platform`, `listing_id` (the platform's id), `url`, `price_eur`, `mileage_km`, `first_registration`, `seller`, `location`, `seller_address` (only what the listing publishes), the seller claims (`accident_free_claim`, `owners_claim`, `hu_claim`, `service_history_claim`, `battery_soh_claim` = battery state of health in % for an electric car), one lease offer as the ad states it (#127: `lease_kind` km / residual / abo, `lease_monthly_eur`, `lease_term_months`, `lease_km_per_year`, `lease_down_payment_eur`, `lease_fees_eur`, `lease_extra_km_eur`, `lease_fewer_km_eur`, `lease_includes` = comma list of insurance, tax, maintenance, repairs, tyres, gap; NULL = not stated; `price_eur` NULL for a lease-only ad), `equipment`, `listing_date`, `last_checked`, `listing_status` (UNDER REVIEW / OWNED / WITHDRAWN), `is_reference` (the car you own), `verdict` (the owner's decision when set from the dossier: "Shortlisted by the owner", "Viewing planned by the owner", "Rejected by the owner: <reason>", each with a `decision` log entry; otherwise an agent's verdict), `notes`, `owner_id`. |
| `listing_snapshots` | captures of the listing as published: `captured_at`, `title`, `price_eur`, `mileage_km`, `description` (verbatim, original language), `attributes_json` (every feature as shown), `source_id`. Never overwritten; a new capture per visit. The price history comes from here. |
| `listing_media` | archived photos in `media/<listing id>/<sha256>.<ext>` (max 1.5 MB each, deduplicated by hash). |
| `valuations` | `kind` `sale_today` (reference only) or `resale_end`, `horizon_years`, `low_eur`, `expected_eur`, `high_eur`, `status`, `valued_date`, `source_id`. |
| `unit_costs` | certain one-off costs of this car: `category` maintenance (a scheduled job due at purchase, with a CERTAIN REPAIR reset) / repairs (a present fault) / tyres / purchase_sale; `item` names the job, `item`, `parts_eur`, `labor_eur`, `diy_hours`, `status`, `source_id`. |
| `maintenance_resets` | a scheduled job done at the start of ownership (`basis` CERTAIN REPAIR / SELLER CLAIM / DOCUMENTED): the schedule restarts for this listing. |
| `research_requests` | the research queue; a listing request is split into unit rows (`parent_id`, `unit`, `level_id`, `shared_id`, `attempts`, `missing`; migration 037, #218), see `docs/api.md`. |
| `research_findings`, `research_matches` | two-run research staging (#253, migration 040, `carlos/staging.py`, design `docs/design-two-agent-research.md`). `research_findings`: one row per staged write of a RESEARCH_A/_B run (`request_id`, `parent_id`, table, kind, finding key, JSON payload); the API shows its id as a negative number. `research_matches`: the comparison of run A and run B per finding key (`AGREED` / `DISPUTED` / `ONLY_A` / `ONLY_B`, `material`, the arbiter's verdict). Catalogue research only, no listing or personal data. `research_requests.unit` also takes `RESEARCH_A`, `RESEARCH_B`, `ARBITER`, `MERGE`; `scope` (JSON) lists the levels a run researches. |
| `inspection_items` | the checklist: `item`, `status` PENDING / OK / PROBLEM / N/A, `checked_date`, `notes`, `reliability_item_id` / `fault_id` / `recall_id` (the one weak point the check comes from, #223; for a recall its result decides whether the recall counts, a fault's does not: its probability already assumes it has not failed). A fault gets an item only when it has an `inspection_action`; `checklist_from_reliability(L)` adds the missing items and is safe to repeat. |
| `listing_events` | the log, the agent's memory: `event_date`, `kind` (found, verification, correction, price, decision, user_data, warning, archive, photos, viewing), `text` (English), `source_id`. |
| `change_log` | audit trail of every write through the API (`table_name`, `row_id`, `action`, `old_json`, `new_json`, `user_id`). |

## Conventions
- **NULL means unknown, never 0.** A missing price, interval or figure stays NULL; the calculation then reports the component as unknown.
- **Every external data point cites a source** (`source_id`) with URL, access date, quality A–D, what it supports and its limitations.
- **Statuses** are English upper-case codes: `VERIFIED` (official or primary source for this engine/variant), `ESTIMATED` (derived, with the derivation in `notes`), `PENDING` (unknown; never with a number), `OBSERVED`, `USER DATA`, `QUOTE`, `OFFICIAL FEE LEVEL`, `PRIMARY`.
- **Free text is English** (notes, log, verdicts, checklist items, descriptions of reliability items, `sources.supports`/`limitations`). Verbatim third-party content (`listing_snapshots.description`, `attributes_json`) keeps its original language.
- **Generations always record** start and end of sale and the facelift year; **engines** record aspiration, injection and timing drive (they identify the engine; since issue #54 they are not scored).
- **Never duplicate** a knowledge row on two levels (#221: for faults the server refuses a second similar fault, 409, when one catalogue variant would carry both; see `docs/api.md`). Re-scope a row with one PATCH that sets the old level column to null and the new one to the id.
- **Archive before delete.** The knowledge tables, `unit_costs`, `valuations`, `maintenance_resets` and `inspection_items` have `archived` (0/1): an archived row stays in the database but the per-account views (`<table>`) hide it from every read and calculation; `<table>_all` still sees it so `archived=0` can restore it. Listings that are no longer for sale are `listing_status='WITHDRAWN'`. `DELETE` through the API removes rows for good (logged in `change_log`) and is used only after the owner's confirmation.
