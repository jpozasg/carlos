# Front end

Plain ES modules served by the app, no build step, no dependencies. `static/`:

| File | Role |
|---|---|
| `index.html` | the shell (header, main, footer, lightbox, toast); applies the saved theme before the first paint |
| `auth.html` | sign-in and invite page (served at `/login` and `/invite/<token>`); a module (`js/auth.js`) that uses `i18n.js` (four languages, a language switch) and the same `h1`/`main` landmarks as the app; the invite page checks the repeated password client side; a failed request shows a message (a proxy 502 or a non-JSON answer included) |
| `css/tokens.css` | design tokens and the themes; `css/app.css` layout and components |
| `js/app.js` | state `S`, data loading, hash router (`#/compare?view=…`, `#/ranking`, `#/listing/<id>`, `#/models`, `#/models/<variant id>`, `#/sources`, `#/settings`, `#/admin` (admins: workers, accounts, research queue, change log), `#/start?step=N`, `#/ranking?quiz=1`, `#/models?make=…&model=…&engine=…`), header, theme and language switching |
| `js/api.js` | `get`, `post`, `patch`, `send`; a 401 sends the browser to `/login` |
| `js/i18n.js` | `t(key, vars)`, plural objects `{one, other}`, `tv(code)` for fixed database codes, language detection |
| `js/ui.js` | formatting (`euro`, `num`, `yrs`), escaping, tags, `store` (localStorage per browser), toast |
| `js/charts.js` | cost composition bars and the break-even SVG |
| `js/quiz.js` | the ranking questionnaire (eight best–worst tasks of four cars; tap or keys 1–4 for first, then last; Enter continues) and the priorities profile with the count behind each weight; used by the Ranking page and the setup wizard |
| `js/pages/*.js` | one module per page, each exporting `render(main, route)` |
| `i18n/en.json`, `es.json`, `de.json`, `pl.json` | the strings; `en.json` is the reference, the others must have the same keys |
| `fonts/` | Bricolage Grotesque (SIL OFL), self-hosted, the one UI family |
| `brand/` | `mark.svg` (symbol used in the header, coloured by the theme), `favicon.svg`, `logo.svg`, `icon-192.png`, `icon-512.png`; `manifest.webmanifest` |

Admins get a **view as** switcher in the header (issue #142): picking an account sets the `carlos_view` cookie and reloads; every page then shows that account as its owner sees it, under a banner "Viewing as …" with a way back. The first-run wizard never opens while viewing as another account.

## Research requests and their parts (#218 phase 2)
`static/js/requests.js` (`partsHtml`): a request lists its parts in stage order (Capture, Variant, Generation, Maintenance, Engine, Gearbox, Tax, Listing) from `parts` (Compare, users: done / in progress / waiting / pending / failed, SKIPPED counts as done, "n of m parts done", missing-item count on a failed part) or `children` (Accounts page, admins: the real status incl. SKIPPED "already existed", "done by request #N", "waits for request #N", worker, attempt, collapsible missing item ids, result). Two-run research (#253): RESEARCH_A, RESEARCH_B, ARBITER and MERGE are parts too (`unit.RESEARCH_A` "Research run 1", `unit.RESEARCH_B` "Research run 2", `unit.ARBITER` "Second opinion", `unit.MERGE` "Merge"), each with the server's `detail` line: staged counts and the last finding, disputes answered, or agreement / written / skipped / flags. Capture is the parent row. A server without these fields shows only the request status. Workers show their current `unit` and `parent_id`. Each part has an icon and text, never colour alone.

## Rules
- **One theme** (issue #181): the default "cluster" look, with light, dark or automatic mode. Its tokens are the custom properties in `tokens.css` (`:root[data-theme="cluster"]`, plus the light variant under `[data-mode="light"]`, repeated under `@media (prefers-color-scheme:light)` for Auto, which has no `data-mode`; `tests/test_theme_tokens.py` keeps the two blocks identical) and a few decorative rules at the end of `app.css`. Text pairs meet WCAG AA (4.5:1) and borders of inputs and unpressed buttons (`--field-border`) 3:1 in both modes; the same test computes the ratios. The data-viz series colours (`--s1`…`--s8`) are one palette validated with the `dataviz` script (light on `#f7f8fa`, dark on `#13161b`); `--s9` is a neutral for the ninth ranking criterion, always shown with its label. A deselected car is greyed with `filter:saturate()`, never faded with `opacity` (that would drop muted text below AA).
- To add a language: add it to `LANGS` in `i18n.js`, translate `en.json` into `i18n/<code>.json` (same keys, same structure), and add the locale to the `Intl` formatting through `LANGS`.
- **Free text from the database is never translated** (notes, log, verdicts, listing captures). Fixed codes (statuses, event kinds, component keys, levels, engine codes such as `WET BELT`) go through `tv()` and the `codes` block of the language files.
- **Unknown is shown as "pending", never as 0** (`PEND()`, `eP()`, `pct()`, `rangeTxt()`, `consumptionTxt()`; no invented defaults such as a unit or a tyre count).
- **Totals reduce to `{sum, missing, n}`** (`sumKnown(rows, pick)`); `totalP()` renders the amount with "+n pending" while a row is unknown, and "pending" when none is known. A per-month cost uses `perMonth(u)`, which adds the "(partial)" tag unless `tco_complete`. Per-month figures come from the server's `known_cost_per_month` / `period_months`. The dossier's Repairs and Maintenance totals are the server's component figures (`components.repairs`, `components.maintenance`, which also count PRESENT history items and are unknown without a mileage or any researched risk); the rows above them (risks, weak points, certain) are shown as parts and are pending while the server's expected part is unknown. `partsLaborP()` prices parts + labour (one missing = partial tag). Sorting Compare by known cost per month puts partial cars after complete ones; the list views say how they are ordered and how many cars the toggles hide; a car added since the last visit joins the comparison (`knownIds` in `store`).
- **Decisions** (dossier): shortlist, plan a viewing, reject with an optional reason (archives the car out of the ranking), undo; `POST /api/ui/decision/<id>`. Compare offers "Shortlisted" as a selection once any car is shortlisted or has a viewing planned.
- **Provisional scores:** `scoreTxt()` marks every score computed from less than half of the weighted data with a "?" and an explanation; the Ranking page explains it once above the list.
- **Target design levels (#174, #168):** each level has its own colour (`.lvl-<level>`). The Models page shows the variant's gearbox, families and body style, its faults (band and shape, or a sourced curve), recalls, TÜV/ADAC figures and review flags; the dossier shows the faults with the chance over the ownership period and the expected cost, the known history and insurance quotes, and the open review flags of every level it inherits (`flagsCard` in `ui.js`, shared by both pages).
- **Reliability sources on Models (#358):** the variant detail lists the `source_keys` (engine and generation level, with the link to the source page) and the `source_ratings` of its engine and generation (`source_keys`, `source_ratings` in `/api/vehicles/<id>`); the listing detail carries the same as `rating_keys` and `ratings`.
- **Every name leads somewhere:** a listing links to its dossier (`carLink`), a variant to `#/models/<id>`, a model, generation or engine to the models tree filtered to it (`modelsHref`). Only verbatim third-party text (source titles, listing captures) stays plain.
- **Manual insurance quote (#399):** the dossier's Costs tab, insurance block, has a "Enter an insurance quote" form for cars for sale (not the reference car): premium (per year or month), insurer, tariff, date, cover, deductible, SF class, a "how to get a quote" note with the car's HSN/TSN and registration and one plain link to a comparison site (nothing is automated). Errors stay inline (`role="alert"`, no toast), the save button uses `busy()`, success is an inline status and the quote table shows "valid until" or "expired" from the server's `quote_max_age_days`. `busy(btn, work)` and `fmtDate(iso)` live in `ui.js`.
- **Insurance quotes by the worker (#218; owner's own account only, #399):** Settings shows this card to admin accounts only, with a note that other accounts enter quotes by hand. The card is an opt-in checkbox card ("Let the research worker get insurance quotes for my cars", preference `insurance_worker_quotes`, off by default, saved at once through `POST /api/preferences` with the login session; shows the date it was switched on and lists the profile fields still missing). The parts view labels the unit `rp_INSURANCE`; admins see a SKIPPED reason as the secondary `result` line.
- **Setup wizard** (`pages/start.js`, `#/start`): shown on the first visit until the preference `onboarding_done` exists (finished or put off), reopened from Settings. Steps: driving, money, search, drivers (policyholder and further regular drivers), insurance (cover, history, usage, discounts), workshop, priorities (the questionnaire), summary. Once finished, every step can be opened from the step rail. Each step saves through `POST /api/parameters` and `POST /api/preferences`, prefilled from what is stored; a choice left empty keeps an older free-text value. The optional steps (drivers, insurance, workshop, charging) carry an "Optional" tag and a "Skip this step" link; a skip posts nothing, so answers already saved stay. Save and the priorities finish are busy while the request runs, and a failure stays as an inline message in the form (`#stepErr`), never a toast. Number fields set one `inputmode`: `decimal` for prices per litre or kWh, `numeric` for whole numbers.
- Numbers wear `font-variant-numeric: tabular-nums`; text never wears a series colour; a legend is present for every multi-series chart.
- Everything the user does in the UI (parameters, questionnaire, viewing mode, account) goes through the same API an agent would use; the UI has no privileged path.
- State remembered per browser (`localStorage`, prefix `carlos.`): mode, language, sort, filters, selection, cost selection, break-even highlight, model filters. Everything else lives in the account.

## Dossier information map (#340)

The dossier answers four questions, one tab each; a piece of data is shown in one place and linked from the others (never copied). The header (photos, score, cost plate) is always visible; on a phone the plate's facts are collapsed.

| Tab | Question | Content (API field) |
|---|---|---|
| Overview | What is this car and how does it rank? | facts and seller claims, decision bar, review flags, to-do gaps, ranking explanation, research levels (`explain`, `research`) |
| Costs | What does each of the eight components cost, from which inputs, from which source? | summary table of the eight `components` (total, per month, share, state); one block per component with its inputs and source: **fuel** (`consumption`, `observations` consumption, `cost_detail.fuel_price_eur_l`, period km), **insurance** (`quotes`, `insurance`, `annual_insurance`), **tax** (`tax`: amount, basis, registration window, status), **maintenance** (certain / scheduled split from `cost_detail`, DIY hours, link to the Maintenance tab), **repairs** (certain / expected split, link), **tyres** (`tyres`: size, price, set, life, fitting), **purchase/sale** (`unit_costs` of that category, price), **depreciation** (`valuations`, asking price, horizon); own one-off costs (`unit_costs`) |
| Maintenance & repairs | What will keeping it running cost? | maintenance plan (`maintenance_plan`, `maintenance_resets`, certain jobs), certain repairs, and the expected cost of the faults as one line linking to Reliability |
| Reliability (#358) | What do published sources say, and what is known to go wrong? | a slot table (Engine, HU defects, Breakdowns) from `reliability_sources`: value as published, edition, source name linking to its page, points, and "n of 3 sources" (a slot without a rating reads "not covered", never 0); one card per source from `rating_keys` / `ratings` (Autoscore, EngineScope, TÜV-Report with the car's age class highlighted, ADAC with its registration year highlighted, GW-Info links per fuel). EngineScope is a link only while `ENGINESCOPE_PERMISSION` is `NONE` (no score rows exist). Footer: gearbox blind spot, KBA recall link, VIN check. Then faults per part (`fault_plan`), recalls (read-only) and the known history of this car (`history`). The Overview plate shows the 0-100 score, the coverage and one meter per slot. `reliability_parts`, `reliability_detail` and `reliability_too_new` no longer exist |
| Viewing | What do I check in person? | the seller's claims to ask about (`ask-seller` card, only what the listing has), checklist (`inspection`), viewing mode. A checklist tap changes only its own row (no redraw), one request per item at a time, and a failed save stays on that item until its next successful save. On a phone the top (photo, score, plate) folds to a strip while this tab or viewing mode is open (`.dossier-top.compact`). Photos: a button opens the picker (gallery or camera), no `capture` attribute. Quiet redraws keep open details, drafts and focus. |
| Log & sources | Where does it come from? | listing archive (`snapshots`, `media`), log (`events`), `sources` of the car, price history |

Moved, not removed: the faults table (Maintenance & repairs to Reliability, grouped by part), insurance quotes (Reliability to Costs), the loose valuations block (Costs, under depreciation).

## Checking changes
Start the app and open the pages in a browser; or headless: `chromium --headless=new --screenshot=out.png --window-size=1280,900 http://127.0.0.1:8000/#/compare` with a session cookie set by a bootstrap page (see `tests/` for the API side). Check phone width (390 px), every theme, light and dark, and the console for errors.

## Reliability sources in the UI (#359, plan #351 section 5)
Compare (details): the Reliability row shows the 0-100 score with "n of 3 sources" (`reliability_sources.present`/`of`); below it one row per slot (`rel_slot_ENGINE`, `rel_slot_HU`, `rel_slot_BREAKDOWNS`) with the slot points and a link to each source rating (`slots[k].sources[].url`; the tooltip gives the published value and edition); a slot without a source reads "not covered", never 0. The CSV has `reliability_engine/hu/breakdowns`. Sources: a fixed "Reliability sources" block (quality, level, terms, link pattern). Ranking: the formula table's reliability text and `rel_ranking_note`. The 36-point part rows are gone from Compare; the Dossier and Models pages are changed by #358.
