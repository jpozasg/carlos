# Compliance checklist (privacy, third parties, licence): what the repo shows, what is open

Not legal advice, and it concludes nothing. The items come from the 2026-11-22 legal audit, re-checked against the repo at 67f98cb with grep and by reading the cited code and docs. The database, the running server, the deployed proxy and every third-party terms page were not inspected. "Question for a lawyer" marks a point where a legal judgement is needed; this file does not give one. For a change that touches an item, answer it in the PR as done / not applicable (why) / open (filed as an issue), and hand open legal points to the owner as a question list (format in SKILL.md).

## Personal data and GDPR (privacy, accounts)
- [ ] **Data map.** Personal data the schema and UI hold: `users` (username, password and token hashes; no e-mail column); `project_preferences` insurance profile keys written before 2026-11-22 (`insurance_holder_gender`, `_birth_date`, `_licence_date`, `_occupation`, `_marital`, `insurance_claims_3y` and the rest; read by no code now, kept in the account's rows); `project_parameters` (postal code; driver age, SF class and cover kept but unread); `listings.seller`, `seller_address`, `location`, `postal_code`, `seller_rating`; `listing_snapshots.description` verbatim; `listing_events` including viewing notes; `listing_media` photos; HSN/TSN; `insurance_data`, `listing_quotes`. Today: no data-map document in `docs/`. Open: write one.
- [ ] **Processors and transfers.** Worker prompts carry the listing URL, the request note and the account id; runs read the account's rows through the API. The worker's insurance quotes were removed on 2026-11-22 (`legacy/insurance-automation`), so no run sends a profile to a comparison site. No DPA or transfer basis is recorded in the repo (searched README, AGENTS.md, `docs/`). Question for a lawyer: is Anthropic a processor or sub-processor, and on which terms? The API refuses the preference `insurance_worker_quotes`.
- [x] **Privacy information for users.** Done 2026-11-22: `/privacy` (`static/privacy.html`, English; bracketed items for the operator; linked from every page). Open: the operator completes the bracketed items. Question for a lawyer: legal bases and wording.
- [x] **Imprint and terms of use.** Done 2026-11-22: `/impressum` shows `DATA_DIR/impressum.txt` (placeholder when absent; `carlos/pages.py`). No terms page. Question for a lawyer: whether and for whom an imprint is required for this service. Keep any owner name or address out of the public repository (configurable outside it).
- [ ] **Cookies and local storage.** Cookies: `carlos_session` (HttpOnly, SameSite=Strict, `Secure` when `X-Forwarded-Proto` is https; `Handler.session_cookie`) and `carlos_view` (set by JS for the admin view-as switcher, no `Secure`). localStorage: keys with the prefix `carlos.` through the `store` helper in `static/js/ui.js` (language, colour mode, filters, sort, selections). No external URL is loaded by `static/index.html` or `static/auth.html`; the font is served from `static/fonts` (`@font-face` in `static/css/app.css`). Open: list them in the privacy text. Question for a lawyer: does this storage need consent?
- [ ] **EXIF and GPS in photos.** `save_media` (`carlos/agent.py`) stores the bytes verbatim after a size and magic-byte check; nothing in the code touches EXIF. Viewing-mode phone photos may carry GPS. Open: strip EXIF on upload, at least for viewing mode.
- [ ] **Retention.** Stated in code or docs: sessions 30 days (`auth.SESSION_DAYS`), insurance quotes expire after 60 days (`config.QUOTE_MAX_AGE_DAYS`), the last five migration backups are kept (`docs/deployment.md`). Not stated: how long listings, photos, `change_log`, `research_requests` and `worker-logs/` are kept (no purge code found); the data directory is a git repository whose history is kept (`docs/deployment.md`). Open: state periods; purge `worker-logs/`.
- [x] **Export and erasure.** Added 2026-11-22: `GET /api/account/export` (Settings, "Download my data") and admin `DELETE /api/admin/users/<id>` with the typed username (export written first; `carlos/account.py`). Open: backups and git history are not erased (see `docs/deployment.md`). Earlier state: a per-listing CSV (Compare page), read-only Markdown dossiers, admin deactivation (`PATCH /api/admin/users/<id>`), and `DELETE /api/agent/<table>/<id>` which removes a listing with its rows and photos only after the owner confirmed it (AGENTS.md). No self-service account export and no account erasure endpoint. Open: an erasure runbook (listings, `media/`, `dossiers/`, preferences, quotes, `change_log`, backups, git history) and a decision on an endpoint. Deleting stays an owner-confirmed act.
- [ ] **Seller personal data.** AGENTS.md limits it to what the listing publishes; the schema has `seller` and `seller_address`; `browser-tasks.md` stores the dealer name only when the ad publishes it. Question for a lawyer: private sellers' names and addresses, notice duties, and whether a multi-user service falls under the household exemption.
- [ ] **VIN and plates.** AGENTS.md: no documents with VIN or plate; no VIN column in the schema; photos may show plates. Tell viewing-mode users to avoid them.
- [ ] **Request logging.** `Handler.log_message` is not overridden, so the default handler writes the client address and request line (including `/invite/<token>`) to stderr and the journal; the proxy keeps its own access log (not inspected). Open: override or truncate, set proxy log retention, say so in the privacy text. See `carlos-threat-model` L1.
- [ ] **Admin access.** Admins see every account's data (README); `change_log` records who wrote. Open: disclose at invitation and in the privacy text.
- [ ] **Security of processing.** In code: scrypt passwords, hashed tokens and sessions, one-time 72 h invite links, a per-client login lock, a localhost bind, a backup before every migration. Gaps are in `carlos-threat-model` (headers, lockout, sessions, file modes). Not covered by the repo: encryption of the data at rest, of backups and of the private data git remote; a breach-notification procedure. Question for a lawyer: what Art. 32 and 33 GDPR require here.

## Third-party sites
- [ ] Every site that supplies stored figures has a row in `register.md` with its terms and robots.txt status (most are `NOT VERIFIED`). Questions for a lawyer, per row: automated or batched reading of listing sites and storing their text and photos (copyright, database rights, the text-and-data-mining exceptions); the CHECK24 automation and the standing broker-information tick (§ 15 VersVermV / § 60 VVG; AGENTS.md decision 2026-11-05); Autoscore shown to every account against its "own use" label; importing the TÜV-Report table from a single copy into a shared database; ADAC data labelled "free, normal browsing" with no cited term; systematic reading of autokostencheck.de variant pages; ev-database.org terms.
- [ ] EngineScope: link only until written permission. The API enforces it (403 while `config.ENGINESCOPE_PERMISSION` is `NONE`). Keep.
- [ ] Anything that shows a premium or recommends an insurer: question for a lawyer whether a "not insurance advice" notice is needed.
- [ ] Postcode data (ODbL): the credit `osm_credit` is rendered in the footer by `static/js/app.js`; README names the licence and source. Question for a lawyer: is that attribution sufficient?

## Accessibility
- [ ] No accessibility statement or audit record exists in `docs/`. Whether the BFSG applies to this service (private or commercial, free or paid) is a question for a lawyer. WCAG 2.1 AA stays a design goal (`carlos-ui-contract`); `bfsg-check` is a checklist only.
